Student Conduct Tracker

A full-stack platform where academic staff can log, review, and discuss student behavior. Featuring threaded comments, karma-based scoring, and a collaborative feed to track conduct over time.

3 months

My Role

Team Lead | Backend Developer.

  • Responsible for designing the database schema and building the REST API with Flask.

  • Led a team of 3 developers, overseeing task delegation, sprint planning, and regular reporting using Agile methodology and Trello for tracking progress and accountability.

  • Developed backend features for threaded commenting and reply systems, tying each interaction to specific users and reviews for behavioral traceability

Tech Stack

Key Features

User Authentication

Secure login and registration with session management.

Review Creation & Management

Allow teaching staff to create and manage reviews for students' and their behaviour.

Student Record Creation & Management

Allow teaching staff to add, remove, and update student records in the database.

Karma Integration

Tracks student karma score overtime, based on the reviews created and voted on by teaching staff.

Promoting Collaboration

Enables communication and coordination between teaching staff, by allowing them to browse, comment and reply to each other's feedback.

REST API

Full API backend powering all frontend interactions.

PostgreSQL Server Integration

Seamless integration with PostgreSQL for efficient data storage, retrieval and querying

What the Project Achieved

The Student Conduct Tracker is a desktop web-based application, which was built using Python Flask and aims to assist teaching staff with monitoring and reviewing student conduct/ behaviour. This system aims to provide a centralized platform to document student behaviour, allow for consistent documentation across various departments and allow staff insight into a student’s conduct before initially working with them.

Limitations

Due to time constraints, there is no functionality which allows the matching of students via a visual or picture. To accurately match a student to an incident the staff must know that student's ID number.


There is also no functionality which allows for the exporting of data, meaning that if staff wanted to run analytics on the data they would have to do so manually by copying and pasting from the database.

Future Improvements

Integration with either external or internal software to allow for data aggregationa nd analysis to uncover patterns and trends in student behaviour
